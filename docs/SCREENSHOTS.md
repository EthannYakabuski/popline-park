# Screenshot provenance

`marketing/screenshots/phone`: 1080×1920. `tablet7`: 800×1280. `tablet10`: 1200×1920.

Each profile has six genuine Godot viewport captures from the implemented game: `01-park-home`, `02-first-line`, `03-boardslide`, `04-line-landed`, `05-locker`, `06-journal`. Each PNG is a complete frame, with no substituted score, UI or scenery. The fresh-profile automated driver uses the game's input action methods, finishes a real campaign ride, then visits the implemented locker/journal. This is **desktop runtime at representative portrait sizes**, not a physical phone/tablet claim.

`07-brickyard-scene` and `08-blue-hour-scene` are extra implemented district previews on the home scene. The capture fixture selects the district palette directly; they are not evidence that a fresh profile unlocked all campaign lines.

Android emulator viewport images, when present under `marketing/screenshots/android-emulator`, are captured by the debug-only native acceptance driver running inside the installed Android app. They show the Godot viewport, excluding Android SDK overlays/system bars. Their exact APK hash and device/emulator facts are in `ACCEPTANCE.md`. Do not describe these as physical-device screenshots or proof of a visible native banner.

The app icon, feature graphic, splash and achievement/leaderboard illustrations are generated artwork. They are deliberately separate from runtime evidence. All store screenshots should be reviewed by the publisher on target devices before submission.
